## 一、这是什么

输入一句文字（如「今日宜忌」「白玖玖，女，2005年6月9日子时排盘」），本地引擎即时返回加工好的玄学分析。所有数据内置 JS，所有计算在用户设备本地同步完成。

**界面唯一依据 =《玄玖灵犀 NT-Xhex.sketch》**（11 个画板，画布 402×874pt = iPhone 16 Pro 逻辑点）。  
本仓的**设计真源只有一份**：那份 Sketch。它是"设计意图"，`modules/UIModule/theme.css` 是「设计稿 → 代码」的单一翻译层，两处一一对应、值互相指认。  
另有 **`玄玖灵犀/docs/设计稿规格说明书.md`**（项目外资料库，不进代码仓；见 `.gitignore` 的 `docs/`）—— 它不是第二份设计规范，而是把 Sketch 里每一个画板、每一个可见图层、每一条动效**逐项量出来、写成可执行的复刻步骤**的说明书（含坐标/尺寸/圆角/字重/行高/对齐/图标几何/动效令牌/响应式断点/边界带规则）。它的用途是：**只要照着它做，就能不看 Sketch 把 UI 1:1 复刻出来**（含动画与动效）。改 UI 时 Sketch 与它必须同步更新。

- **黑白灰配色（例外制）**：全站**只允许黑白灰**（+ 危险红 `#FF5733` 作危险语义），**唯二例外**是「宜忌（`--nt-yi` 吉绿 / `--nt-ji` 凶红）」与「五行（`--wx-金/木/水/火/土`）」这两组业务语义色，且**双主题适配**——浅色用压底的深色版、深色用跳底的浅色版（都在 `theme.css` 的浅色 `:root` 与深色 `.nt-dark` 各存一套值）
- **黑白双主题（v3.1.0 起只有两种来源）**：**① 跟随系统**——读得出设备/系统的浅色或深色模式时，界面跟着系统走；**② 搜索框关键词手动切**——输入「切换主题」等切换词即翻转并记住（也可说「深色模式」「浅色模式」「暗黑」「反色」等）。**手动优先于系统**，清除缓存则回落跟随系统。已**删掉「北京日出日落」判定**（不再有 07:00/17:10 时区逻辑）。切换时底色/纸面/文字/图标在 320ms 内交叉渐变（门控类 `.nt-theme-fade`，视觉全在 `theme.css`，三端同一份）。主题切换只在搜索框内实现，三端（PWA / 小程序 / uni-app）行为一致
- **转场**：双层视差（微信「设置 → 子页」同款）—— 底层旧页左移压暗、顶层新页右滑入；PWA/uni-app 无「上一页」DOM，降级为单层右滑入

> **卡高 600 / 528 不是拍出来的数**：它等于「卡顶到页脚之间的全部剩余空间」，故 `.nt-dl-card` 用 `min-height:100%` 撑满 ——  
> 内容页 `874 − 46 − 30 − 24 − 174 = 600`；结果页再扣掉双按钮 `48 + 24` → `528`。换任何屏高都自动成立，内容更长时卡片自己长高，绝不裁字。

> **⚑ 图标铁律：Sketch 的 `frame` 是「路径中心线」的包围盒，描边是往外溢出的。**  
> 所以量出来的 `7.5825 × 16` 是**中心线盒**，真正画出来的墨迹要比它大**一个线宽**：`7.5825 + 1.5 = 9.08 →` 实际 `8.8628 × 17.0606`（横竖各扩 `0.75`，即半个线宽）。  
> 两条推论，都在代码里落实了：  
> ① **绝不要为了「给描边让位」而把路径往内缩**（曾经缩了 `0.75`，开合角从 90° 变成 100°、尖角也被磨圆）。路径必须跑满设计稿的两端极值。  
> ② **SVG 当 `background-image` 用时，最外层 `<svg>` 的溢出是裁掉的，且不可靠地被 `overflow` 覆盖。** 所以 `viewBox` 必须取**墨迹盒**、CSS 盒子也取同一个值，两者 1:1，描边才不会被切。  
> 端头样式住在 Sketch 的 `style.borderOptions`（`lineCapStyle: 0` = 平头 Butt，`lineJoinStyle: 0` = 尖角 Miter），**不在 `shapePath` 节点上**；本稿 537 处出现全是 0。

### 4. 首页居中的那点细节

设计稿把首页主体块（`24,332 354×212`，中心 `438`）**居中于整张画布**（画布中心 437），**不是**居中于「导航底–页脚顶」的剩余区（那儿的中心在 453.5）。  
原因是上边界带（59+50=109）比下边界带（34+12+28=74）高 35，自由区整体下移 17.5。

`theme.css` 里用 `--band-top` / `--band-bottom` 两个 token 表达这条矫正，给 `.nt-hero` 补一段等于「上带 − 下带」的下内边距，把视觉中心拉回画布中心 —— 换任何屏高都成立、不含魔数。


### 5. 动效（少 · 快 · 统一）

原则：**三层状态动效 + 常驻/过渡/开屏/弹窗动效（滚动建议 / 强调光环 / 主题切换 / 开屏淡出 / 弹窗进出场），不堆特效**。全部时长/缓动取自 `theme.css` 顶部令牌，页面里不出现任何裸数字。  
（第 1–3 层是「状态变化」——转场 / 入场 / 按压；第 4、5 层是「常驻自循环」；第 6 层是「主题切换过渡」；第 7 层开屏淡出、第 8 层弹窗进出场是「进出场」，均与前三层不同源，故单列。）

**时长与缓动令牌**

| 令牌                             | 值                            | 用在哪                                                                                                    |
| ------------------------------ | ---------------------------- | ------------------------------------------------------------------------------------------------------ |
| `--ease-standard`              | `cubic-bezier(.4, 0, .2, 1)` | 全局唯一曲线，入场/转场/状态切换共用                                                                                    |
| `--d-press`                    | `120ms`                      | 按钮按下、状态切换、hover                                                                                        |
| `--d-drawer`                   | `280ms`                      | 浮层 / 模态框（**进场** `nt-rise`）                                                                               |
| `--d-modal-out`                | `200ms`                      | **弹窗出场** `nt-fall`（退场比进场快一档；三端「先播后摘」）                                                                 |
| `--d-page`                     | `320ms`                      | 页面转场、内容入场                                                                                              |
| `--d-theme`                    | `320ms`                      | **主题切换**：界面色板交叉过渡                                                                                      |
| `--d-splash`                   | `400ms`                      | **开屏页退场**（v3.1.0：品牌组缩放到起始页比例 `nt-splash-brand-out` + 背景/副标淡出 `nt-splash-bg`）                          |

**第 1 层 · 页面转场**

| keyframe                   | 用途                                                             |
| -------------------------- | -------------------------------------------------------------- |
| `nt-tf-in` / `nt-tf-out`   | 顶层：新页自右滑入 / 旧页自右滑出                                             |
| `nt-px-fwd` / `nt-px-back` | 底层：旧页向左让位 33%（视差）                                              |
| `nt-dim-in` / `nt-dim-out` | 中间压暗遮罩 0 → .24                                                 |

**第 2 层 · 内容错落入场（只在冷启动首屏）**

唯一入场 keyframe `nt-rise`（`translateY(16px) → 0` ＋ 透明度 `0 → 1`），按视觉从上到下每级 `40ms`：

| 顺序 | 元素                                   | 延迟                      |
| -- | ------------------------------------ | ----------------------- |
| 1  | Logo / 页名 `.nt-page-h` / `.nt-brand` | `0ms`                   |
| 2  | 标题 / 正文卡 `.nt-dl-card`               | `40ms`                  |
| 3  | 搜索胶囊 / 双按钮 `.nt-dual`                | `80ms`                  |
| 4  | 免责说明 / 页脚 `.nt-foot`                 | `120ms`                 |
| —  | 设置行的 4 张卡（`:nth-child`）              | `40 / 80 / 120 / 160ms` |

**⚠️ 只在「冷启动首屏」播，页面切换时不播。** 切页已经有整层滑入承担全部位移；若内容再各自上浮一次，同一块内容会一边被整层平移、一边自己做 `translateY` + 淡入，两种动效同期叠加就是用户实测到的「重影」。所以这条动画整体挂在门控类 **`.nt-cascade`** 之下，由各壳在首屏渲染时挂上、首次切页即摘掉：

| 形态      | `.nt-cascade` 挂在哪                                   | 何时摘掉                               |
| ------- | --------------------------------------------------- | ---------------------------------- |
| PWA     | `#v-home` 的初始 class（恢复上次结果时由 `show(name, true)` 现挂） | `show()` 里对所有视图 `toggle(…, false)` |
| 微信小程序   | 根节点 `.page`，由 `data.boot` 控制                        | `go()` 里 `boot: false`             |
| uni-app | `.page` 的 `pageClass`，由 `data.boot` 控制              | `go()` 里 `boot = false`            |

`boot` / `nt-cascade` **只能单向降下、不能回加**：反过来用「切页时加抑制类、结束再摘」的写法，摘掉那一刻 `animation-name` 会从 `none` 变回 `nt-rise`，等于凭空重启一次动画 —— 那就成了「切换完还有一个动画重复播放」。改回「每次进页都错落」只需让各壳持续保留 `.nt-cascade`（一行的事，别处不动）。

**第 4 层 · 滚动搜索建议（轮换，不是入场）**

首页搜索框为空时，一列**真实示例问句**在 48pt 高的胶囊里逐条轮换 —— **节奏与百度首页搜索框同款：一条停住约 5s 让人读完 → 再用约 0.5s 整体上滑一行换下一条**（刻意不做匀速滚动条：连滚的词条永远读不完整）。文案不是写死的提示语，而是 `settings.js` 的 `searchHints`（单一真源），三端只负责遍历渲染。

| 结构 / 规则           | 说明                                                                                                                                                                                                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| DOM               | `.nt-pill` > `.nt-ph`（裁切窗，`left:24px` `right:48px` `overflow:hidden`）> `.nt-ph-track`（整列）> N 个 `.nt-ph-item`                                                                                                                                                             |
| 轮换节奏              | `@keyframes nt-ph-step`：每个档位 = 停留 `11.364%`（5.0s）+ 上滑 `1.136%`（0.5s）= `12.5%`（5.5s），一圈 `--d-ph-rotate: 44s`（8 条）。缓动函数对每个 keyframe 区间**分别生效**，所以停留区间不动、上滑区间缓入缓出                                                                                                           |
| 无缝衔接              | track 末尾**再放一份首词条**。整列高 `(N+1)×48 = 432`，滑到 `-N×48 = -384px` 时窗口里那一行与第一行逐像素相同 → 动画从 `100%` 回到 `0%` 看不出接缝。位移写成 `--pill-h` 的整数倍（`-1×48 … -8×48`），一眼能看出「滑了几条」                                                                                                               |
| ⚠️ 与条数绑定          | keyframe 的档位个数/百分比**必须与 `searchHints` 条数一致**（8 条 → 12.5%/档，9 条 → 11.11%/档），同时改 `--d-ph-rotate`（条数 × 5.5s）。这是 CSS 与数据之间唯一的耦合点，`theme.css` 与 `settings.js` 两处注释互相指向                                                                                                        |
| 宽度上限              | 可用横向空间只有 `200pt`（`272 − 左内边距 24 − 右端放大镜键 48`），17pt 字下约 **9 个汉字**。`right` 必须让出那 48pt，否则超长词条会钻到发送键底下（已实测复现并修掉）；`.nt-ph-item` 另带 `overflow:hidden + text-overflow:ellipsis` 兜底                                                                                              |
| 让位规则              | **输入非空 或 已聚焦** → 给 `.nt-pill` 加 `.nt-ph-off`，`.nt-ph` 整体 `opacity: 0`（两种情形都该让位：① 这就是百度首页的行为 —— 一点进搜索框提示词就让位给光标，输入时当然更不显示；② 微信官方文档写明「input 仅在 focus 时表现为原生组件」，聚焦态它层级高于 WebView 里的一切元素，词条会被直接盖住 —— 干脆主动隐掉，不赌层级）。只写「让位时隐藏」这一条，**不写 `:not()`** —— WXSS 对 `:not` 支持不稳，三端容易不一致 |
| ⚠️ 切页要清 `focused` | 小程序壳里 `go()` 的 patch 必须带 `focused: false`。不清的话：点一下搜索框（`focused=true`）→ 点「关于」→ 返回首页时新渲染的 `<input>` 其实没聚焦，但 data 里还是 `true`，滚动词条就再也不回来了                                                                                                                                    |
| 输入穿透              | `.nt-ph` 带 `pointer-events: none`，点击照常落到 `<input>` 上                                                                                                                                                                                                                     |

**第 5 层 · 搜索框常驻强调光环（呼吸，不是入场）**

在胶囊外缘套一圈**柔晕呼吸**（v3.1.0 起），让「这里能输入」这件事在任何时刻都有一点点视觉牵引。  
v3.0.6 曾做「1px 细环 + 极淡柔晕」；v3.1.0 按用户反馈「白边不好看」**去掉细环（白边）**，只留一层柔晕，并把颜色**加深**（浅 `.10/.20`、深 `.10/.24`）、范围**收小**（blur 由 3↔8px 收到 2↔5px、缝隙 2px→1px）。

| 结构 / 规则       | 说明                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ⚠️ 为什么要有独立子节点 | **一个 CSS 元素只有一条 `animation` 槽位**（`animation` 是简写）。`.nt-cascade .nt-hero-pill` 已经用掉了胶囊自己的槽位（`nt-rise` 入场），再加一条光环动画会直接把入场顶掉。所以光环放在**真实子节点 `.nt-halo`** 上 —— WXSS 没有 `::before/::after`，也不能写 `a, b: infinite` 这种动画列表语法，只有真实元素这一条路                                                                                                                                                              |
| DOM 位置        | 必须是 `.nt-pill` 的**第一个子节点**（`position: absolute` 的静态位置与文档序无关，但放首个子节点可保证它永不在输入框之上）                                                                                                                                                                                                                                                                                                            |
| 几何            | `left/right/top/bottom: calc(var(--halo-gap) * -1)`（v3.1.0 `--halo-gap: 1px`，比原 2px 收小）+ `border-radius: var(--r-pill)` —— 柔晕贴胶囊缘收小一圈。v3.1.0 已删 `--halo-ring-w` / `--nt-halo-ring`（细环白边）                                                                                                                                                                                                                      |
| 单层柔晕          | `@keyframes nt-pill-halo`：`0%/100%` → `0 0 2px 0 var(--nt-halo-soft)`；`50%` → `0 0 5px 0 var(--nt-halo-glow)`，周期 `--d-halo: 4400ms`。<br />v3.1.0 只留**一层柔晕**（删了细环白边）：`blur` 由 2px（弱）呼吸到 5px（强）—— 比旧款 3↔8px 收小。`box-shadow` 不外扩布局、不盖住胶囊，不与"全站无阴影"冲突 |
| 配色            | 柔晕 `--nt-halo-soft` `.10`（浅）/ `.10`（深）→ `--nt-halo-glow` `.20`（浅）/ `.24`（深）—— 比旧款（`.04↔.11` / 深 `.05↔.13`）**加深**一档。深色底上用白柔晕才看得见                                                                                                                                                                                                                           |
| 不挡点击          | `.nt-halo { pointer-events: none }`。实测 `document.elementFromPoint(胶囊中心)` 返回的是 `<input>` 本身                                                                                                                                                                                                                                                                                                  |
| 微调入口          | 只想更细/更粗 → 改 `--halo-gap` / `--halo-ring-w`；只想让呼吸更明显 → 改 `--nt-halo-soft` / `--nt-halo-glow`。**不必动任何一条 keyframe**                                                                                                                                                                                                                                                                            |

**第 6 层 · 主题切换过渡（v3.0.6 新增）**

用户要求「切换主题要有动画」。做法**不是**加一层遮罩或闪一下，而是让**界面色板自己交叉过渡**：底色 / 纸面 / 文字 / 线性图标在 `--d-theme(320ms)` 内从旧主题平滑走到新主题，而不是硬切。

| 结构 / 规则                  | 说明                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 开关                       | 根节点上的门控类 **`.nt-theme-fade`**。带着它，`theme.css` 里那一大串「带界面色的类」才有 `transition`；摘掉就等于关掉这个动效                                                                                                                                                                                                                                                                      |
| 为什么必须门控                  | ① 浏览器端首帧要先按系统偏好落一次主题（浅色 → 深色），常开的话冷启动会「先白后黑闪一次渐变」；② 常开会把日常的按压/悬停也一起拖慢                                                                                                                                                                                                                                                                                       |
| 三端谁挂、何时挂                 | **PWA** → `public/pwa/app.js` 在**首次** `applyTheme()` 之后、**同一 tick 内**挂到 `<html>`（首帧之前，所以不闪，又在用户第一次切换前早就生效）；**小程序** → `dist/mp-weixin/pages/index/index.wxml` 根 `<view class="page">` 上**静态写死**；**uni-app** → `pages/index/index.vue` 根 `<view class="page">` 上静态写死（两者首帧就是正确主题，不存在闪烁）                                                                        |
| 为什么不用 `.nt-theme-fade *` | WXSS 官方支持的选择器列表里**没有通配选择器**，为三端一致只能**显式枚举类名**。好处是这份名单顺带成了一份清单 ——「哪些元素带界面色、需要随主题过渡」，缺了谁一眼看得出来                                                                                                                                                                                                                                                                |
| ⚠️ 按压反馈不能被吃掉             | 门控选择器是 `.nt-theme-fade .x`（特异度 `0,2,0`），**高于** `.nt-setrow` / `.nt-pill` / `.nt-pill-btn` 自己的 `transition`（`0,1,0`）—— 被点名的元件，它自己那行 `transition` 会被**整条替换**（不是叠加）。所以本块必须把 `opacity` / `transform` 也一起写上（用 `--d-press`），否则按钮按下淡出、设置卡按下缩放会因为没有 transition 而瞬间硬切。代价：`.nt-setrow` 桌面端 hover 换底由 120ms 变成 320ms —— 同一个 `background-color` 不可能「换主题时慢、悬停时快」，这是刻意的取舍 |
| 图标也要跟着走                  | 线性图标靠 `filter: invert()` 反色。`.nt-icon` 基线显式写了 `filter: invert(0)`（`none` 无法插值，只能硬切），并把 `filter` 列进过渡 → 深浅切换时图标是「灰→白/黑→灰」地走，不会出现「底和字在渐变、图标已经跳色」的错帧                                                                                                                                                                                                           |
| 已知例外：品牌 Logo             | Logo 是**换图**（`logo.png` ↔ `logo-white.png`），换图不参与 CSS 过渡，所以它在 t=0 就完成切换。观感上表现为「随底色一起消失、再随底色一起浮现」，可接受。（可选优化：实测 `logo-white.png` 与 `invert(logo.png)` **逐像素相同**，将来可以改成纯 CSS `filter: invert(1)` 让 Logo 一起渐变，同时省掉三端的换图逻辑。）                                                                                                                                     |
| 实测                       | 见「六、验证」末条：切换瞬间 `body` 与文字色采样到中间值（如 `rgb(221,221,221)`），400ms 后落到终态，证明过渡真实运行                                                                                                                                                                                                                                                                                 |

**第 7 层 · 开屏页 → 起始页「品牌交接」（v3.0.7 新增开屏页，v3.1.0 改为缩放交接）**

冷启动的品牌瞬间：整屏居中「品牌组（Logo 85.69×96 + 玄玖灵犀 28pt）+ 副标 演乾坤·知天命 12pt 黑30%」，停留 1.2s 后退场。视觉全在 `theme.css`（`.nt-splash*` + `@keyframes nt-splash-brand-out` / `nt-splash-bg`），文案走 `settings.js` 的 `about().splash`，三端一致。

**第 8 层 · 弹窗进出场（v3.0.7 补出场）**

「清除缓存」确认弹窗之前**只有进场**（`nt-rise` 上浮淡入 280ms），v3.0.7 补上**出场**（`nt-fall` 淡出下沉 200ms，`--d-modal-out`，比进场快一档、退场干脆）。

| 结构 / 规则                  | 说明                                                                                                                                                                                                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 出场 keyframe             | `@keyframes nt-fall`：`opacity 1→0` + `translateY(0→8px)`。加 `.nt-mask-out` 即播放（`animation: nt-fall var(--d-modal-out) both` + `pointer-events:none`）                                    |
| 退场「先播后摘」             | 三端都用「双状态」：`clearOpen`（卸载）+ `clearClosing`（播退场类）。关闭时先挂退场类播 200ms，播完再卸载节点；**直接卸载则退场动画来不及播**。`doClear`（确认）也复用同一收尾，把切页/清输入/落主题推迟到退场播完，避免遮罩还在淡出时页面已跳走造成重影 |
| 三端落地                   | **PWA** → `app.js` 的 `openMask/closeMask`（`display` 切换 + 延时摘）；**uni-app** → `settings.vue` 的 `clearClosing` + `closeModal()`；**小程序** → `index.js` 的 `clearClosing` + `closeModal()`（定时器句柄统一在 `onUnload` 清掉）          |

**六个必须记住的坑（都写进 `theme.css` / `index.js` 注释了）**

1. 入场动画用 `animation-fill-mode: backwards`，**不能用 `both`** —— 动画声明优先级高于普通声明，`both` 会让动画终值一直压住 `:active` 的 `transform`，按压反馈直接失效。
2. 入场动画**不要挂到 `.nt-nav-*` 上**（同上，`transform` 冲突）。
3. 小程序端「返回」必须走双层结构（`.nt-stage` 的 `layerFront` / `layerBack` 要按方向**交换**）。旧写法永远把新页放顶层，返回时会自右滑入 —— 方向是反的。
4. **转场两层必须各自不透明**（`.nt-layer { background: var(--nt-bg) }`）。静止态两层渲染同一页、靠 `z-index` 分先后；若两层透明，330ms 后同步 `layerBack` 时底层重建重播的动画会从顶层内容背后透出来 —— 这就是「切换后还有一个动画重复播放」的真正来源。
5. **小程序转场收尾必须分两帧**（`dist/mp-weixin/pages/index/index.js` 的 `go()`）：先 `setData({ layerFront: to })`（返回时顶层停在 `translateX(100%)` 屏外，内容在「看不见的地方」重建），下一帧（20ms 后）再 `setData({ navAnim:'', layerBack: to })` 让位移归位。**并成一帧**（旧写法）时，返回时顶层会在同一帧里既被清空重建又瞬间归位，而顶层是压在正确画面之上的不透明面 → 闪出一次纯底色，就是用户反馈的「返回某个页面会闪烁一下」。只有「返回」会踩到这个坑：前进时顶层本就是新页，第一步是空操作。
6. **一个元素只能有一条动画**：想给某个元素再加一条常驻动画前，先确认它的 `animation` 没被占用（`.nt-pill` 就被 `.nt-cascade` 的入场占着）。加不上时不要改 `fill-mode` 去凑，直接补一个真实子节点承载新动画 —— 这也是 `.nt-halo` 存在的全部理由。
7. **`transition` 是"整条替换"不是"逐条叠加"**：`.nt-theme-fade .x`（`0,2,0`）会顶掉 `.x` 自己写的 `transition`（`0,1,0`）。给某个类加常驻过渡前，先确认没有更具体的选择器在它身上另写了一条 `transition`，否则被顶掉的那个元件会丢掉自己的按压节奏。主题过渡块就是这么把 `opacity` / `transform` 一并写进去的。

> **无障碍（`prefers-reduced-motion`）降级代码已按用户要求整体撤除**（v3.0.6 起）。本项目不做无障碍降级：动效在所有环境下全量播放。`theme.css` 里不再有任何 `@media (prefers-reduced-motion)` 块。

### 6. 深色模式下「上下滑动露白底」的根因与三端对策

`theme.css` 里 `page { background: var(--nt-bg) }` 只染**页面节点自己**。上下滑动越界（橡皮筋 / 下拉回弹 / scroll chaining）时露出来的是**容器背后那一层**和浏览器原生 UI，它们不跟 CSS 变量走 —— 深色下就是一条白底。三端各自的对策：

| 形态         | 做法                                                                                                                                                                                                                                  |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 浏览器 PWA    | `.nt-dark` 挂在 `document.documentElement`（走 `theme.js` 的 `apply()`，不是只挂 `#app`）→ `html` / `body` 的 `--nt-bg` 一起转黑；再补 `overscroll-behavior: none` 断掉滚动链；`color-scheme: light / dark` 让原生控件与回弹底色跟随                                     |
| uni-app H5 | `pages/index/index.vue` 的 `syncWindowTheme()`：`Theme.apply()` + 行内写入 `html` / `body` 底色 + 同步 `<meta name="theme-color">`。用行内样式是为了不受 uni-app 基础样式的层叠顺序影响                                                                             |
| 微信小程序      | `wx.setBackgroundColor({ backgroundColor, backgroundColorTop, backgroundColorBottom })`，在 `dist/mp-weixin/app.js` 的 `onLaunch` / `onShow`，以及 `pages/index/index.js` 的主题切换、清除缓存处各调用一次。`app.json` 里那个 `#ffffff` 只是首帧默认值，**运行时以本调用为准** |

配套：深色下的**纸面必须提亮**（`--nt-paper: #1a1a1a`、弹窗 `--nt-elevated: #2c2c2e`）。去掉描边后层级全靠明度差，原来的 `#0a0a0a` 与纯黑底几乎不可分，卡片会「消失」。

### 7. 响应式（HIG：字号永不随视口缩放）

| 视口                | 规则                               |
| ----------------- | -------------------------------- |
| `< 360pt`         | 左右留白 `24 → 16`（HIG 最小边距）；搜索胶囊改满宽 |
| `360–767`         | 完全按设计稿：留白 24、卡片满宽、**字号不变**       |
| `768–1023`（平板）    | 内容居中，最大宽 `640`（留白由居中产生，不拉伸卡片）    |
| `≥ 1024`（电脑 / 网页） | 内容居中，最大宽 `720`                   |

已实测（Chrome，逐断点量容器与字号）：320 → 留白 16 / 胶囊 288 满宽；375·402·430 → 留白 24 满宽；768 → 居中 640（x=64）；1024·1440 → 居中 720（x=152 / 360）；**22px / 17px 字号在所有断点恒定**。

## 四、核心架构（模块化 · 单一引用）

一个项目包体、一个代码库。引擎 / 数据 / 存储 / 设置 / 会话 / 视觉均为**唯一真源**（`modules/`），各形态「只加载自己用到的模块，忽略其余目录」，选择清单统一在 `tools/platform-modules.json`。

- 主形态：微信小程序；浏览器 → PWA 网页（可安装为 APP）；uni-app → H5 / Android / iOS / 鸿蒙
- 平台语法不同的部分（小程序 WXML/WXSS、Vue、DOM）保留各自薄壳，**公共行为逻辑一律提到共享模块**
- 跨平台**不用软链接**（微信打包器不跟随指向项目外的软链），用「生成产物 + 单一真源」同步
- 品牌 / 版本 / 备案 / 版权文案单一真源 = `modules/SettingsModule/settings.js` 的 `about()`

## 五、各形态运行与部署

### 1. 微信小程序（主形态）

**方式 A（无需构建，直接打开）**：`dist/mp-weixin/` 是一份完整原生小程序。用「微信开发者工具」直接「导入项目」选择 `dist/mp-weixin/` 即可预览/编译/上传。

> ⚠️ 必须选 `dist/mp-weixin/`（含 `app.json`），**不能选仓库根目录**（根目录无 `app.json`，会报「no found app.json」）。  
> ⚠️ 引擎文件 + 静态资源是**单一真源 `modules/` 的生成产物**（普通文件，非软链）。改了 `modules/` 或 `static/icons/` 后：`node tools/sync-mp.js`（校验：`node tools/sync-mp.js --check`）。  
> ⚠️ 微信 IDE 会在 `dist/mp-weixin/` 自建 `app.miniapp.json`、`project.miniapp.json`、`project.private.config.json`、`i18n/`、`miniapp/`，并把 `project.config.json` 写成 `"projectArchitecture": "multiPlatform"`。这些是 **IDE 本地产物、不入库**（已进 `.gitignore`）；发现后清理并在 IDE 里重新导入，否则会被当成「小应用」架构打开白屏。

**方式 B（uni-app 构建）**：`npm install && npx uni build mp-weixin`

### 2. 浏览器 PWA（无需构建，直接运行）

必须从**项目根目录**起静态服务（`public/pwa/` 内的相对路径 `../../modules/…` 才能解析）：

```bash
cd <仓库根>
python3 -m http.server 8090      # 8080 常被本机 WebDAVNav 占用，故用 8090
# 访问 http://localhost:8090/public/pwa/index.html
```

自动注册 Service Worker（离线可用）；检测 `beforeinstallprompt` 显示安装引导。

### 3. 多端原生（Android / iOS / 鸿蒙）

`npx uni build app`。业务逻辑复用 `modules/`，无需改代码。

## 七、历法算法说明

`modules/AnalyzerModule/lunar.js` 为精确离线历法（纯 JS、零网络、零依赖）：

- **廿四节气**：NOAA 太阳黄经 + 逐日跨黄经扫描（东八区），对照 2026 真实节气全部吻合
- **四柱**：年柱立春换年、月柱 = 节气定月建 + 五虎遁、日柱 = 甲子纪日、时柱 = 五鼠遁
- **建除十二神**：节气月建 + 日支推值日
- **日主旺衰**：得令 / 得地 / 得势计分

`db.js` 存干支 / 时辰 / 五行生克 / 建除宜忌 / 地支六冲 / 姓名拆字五行 / 五格数理等规则数据（大白话注释）；`ganzhi.js` 委托 `lunar.js`，三壳自动受益。
